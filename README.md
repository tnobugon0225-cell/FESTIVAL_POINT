# FESTIVAL POINTS v2

学祭などのイベントで使う、参加者アカウント式ポイント管理Webアプリです。

## 主な機能

- 参加者の新規登録 / ログイン
- 参加者本人のポイント表示（約5秒ごとに自動更新）
- 公開ランキング
- 参加者ごとのマイQR
- スタッフがQRまたは名前検索で参加者を呼び出し
- スタッフだけがポイント加算 / 減算
- AさんからBさんへのポイント移動（奪取・譲渡）
- ポイントを0未満にしない制御
- 全操作履歴と「どのスタッフが操作したか」の記録
- スタッフごとの個別アカウント
- 管理者によるスタッフ追加 / 無効化
- bcryptによるパスワードハッシュ化
- 簡易ログイン試行制限

## 起動

Node.js 18以降を推奨します。

```bash
npm install
npm start
```

参加者画面: `http://localhost:3000/`

スタッフ画面: `http://localhost:3000/admin`

## 初期管理者

初回起動時、スタッフが1人もいなければ以下で管理者が作成されます。

- ID: `admin`
- パスワード: `change-me-now`

**本番では必ず環境変数で変更してください。**

例（macOS / Linux）:

```bash
ADMIN_USERNAME=festival-admin \
ADMIN_PASSWORD='十分に長いパスワード' \
SESSION_SECRET='ランダムで長い文字列' \
BASE_URL='https://あなたの公開URL' \
npm start
```

Windows PowerShellでは `$env:ADMIN_USERNAME="..."` のように設定してください。

## QRについて

参加者のQRには `/admin?code=参加者コード` のURLが入っています。
スタッフがログイン済みのスマホでQRを読み取ると、その参加者が管理画面に表示されます。

本番では `BASE_URL` を実際のHTTPS公開URLにしてください。`localhost` のままだと別のスマホからQRを使えません。

## 不正防止として入れているもの

- 参加者用APIからポイント変更はできない
- ポイント変更・移動はスタッフログイン必須
- スタッフごとのアカウントと監査履歴
- パスワードは平文保存しない
- ログイン試行回数の簡易制限
- ポイントは0未満にならない
- 1回の操作は最大100,000pt
- セッションCookieはHttpOnly / SameSite=Lax

## 本番公開前に追加推奨

このコードは学祭用の小〜中規模運用を想定したスターターです。インターネットに公開する場合は以下も推奨します。

1. HTTPS対応のホスティングを使う
2. `SESSION_SECRET` と初期管理者パスワードを必ず変更
3. 定期的に `data/festival.db` をバックアップ
4. 参加者数がかなり多い場合はSQLiteからPostgreSQL等へ移行
5. 必要に応じてCSRF対策・Redis等のセッションストア・より厳格なレート制限を追加

## データの初期化

テストデータを全部消したい場合は、サーバー停止後に `data/festival.db` を削除して再起動してください。
